Architecture Review

GW Observer

A Windows-native C++20 / DirectX 11 replay viewer for Guild Wars 1 GvG matches. Single VS2022 project, all dependencies vendored in-tree, secrets injected at compile time from a private sibling repo. ~275 source files — but the architectural mass is concentrated in a handful of places.

System shape

Three genuinely independent pillars (cloud distribution, GW asset decoding, replay ingestion) feed one heavily-centralized presentation layer.

Main.cpp (WinMain, msg pump, crash dumps, BASS load)
  └─ MapBrowser  ── the app singleton: DeviceResources, MapRenderer, DATManager,
     │              cloud stack (HttpClient/S3Auth/MatchIndex/SyncEngine/UpdateChecker),
     │              ~30 modular draw_*.cpp ImGui panels
     └─ ReplayWindow[]  ── one per open match; OWN D3D device + ImGui context + renderer
                          + the entire analytics/overlay/audio/camera feature set

Data plane:   Gw.dat → GWUnpacker/DATManager → FFNA/BB8/BB9/ATEX parsers → caches → renderer
Replay plane: R2 bucket → tar.gz → infos.json + Agents/*.txt.gz + StoC/*.txt.gz → ReplayContext
Render plane: shadow → water-reflection → scene (sky/terrain/props/water) → overlays → ImGui → Present

What's done well

  • Phased, time-budgeted loading (Validate→…→Ready, 30 ms/frame budget) keeps windows interactive during multi-second map loads — applied consistently across props, agent models, and derivations.
  • Disciplined async/GPU split: DAT reads + parsing happen off-thread with an explicit "no D3D calls" contract; all GPU resource creation is confined to the render thread. Multi-context ImGui is handled correctly (save/restore at every entry point — the hard part).
  • The newer parser generation is genuinely defensive (BB9AnimationParser, VLEDecoder, BB8Geometry, FileReference) — bounds-checked, std::optional, catches decoder throws. Reverse-engineering provenance preserved in comments.
  • Clean secret layering: safe-by-default public repo, __has_include compile-time override, gitignore discipline verified end-to-end, only hashes (never plaintext keys) in the private repo, constexpr dev-mode dead-strips debug UI.
  • AgentOverlay is a model DX11 sub-pass: single instanced draw, reserved CB slot b4, documented state-restoration contract.
  • Robust field ops: symbolized minidump handler, R2 pipeline with dry-run/validation/status tracking, atomic download hygiene (tmp+rename, retry/backoff, offline fallback), zip-slip + decompression-bomb guards.

Cross-cutting risks

These recurred across subsystems — the number of agents that independently flagged each is noted.

1 The ReplayWindow monolith all 4 agents

29,161 lines / 1.24 MB in one translation unit (docs claim ~17K — stale by 70%), ~140 methods, several hundred fields spanning rendering, data derivation, every analytics panel, audio, cameras, and per-map hacks. The main window already proves the fix — its 30 panels live in separate draw_*.cpp files; the replay window never got that treatment. Compounded by an implicit ~21-boolean-flag derivation DAG in Tick() whose ordering lives only in comment prose.

2 Shipping-quality defects in hot paths 3 agents

  • Hardcoded D:\Guild Wars OBS\...\debug-dddcee.log writes opened every 60 frames at ~6 sites in MapBrowser.cpp + AgentOverlay.cpp — machine-generated #region agent log blocks left in release.
  • Null-deref UB on the fresh-install path: Main.cpp:216 calls g_map_browser->GetDefaultSize() before the object is constructed at :231 (works only because the method ignores this).

3 Parsing safety on untrusted / corrupt input 2 agents

  • FFNA_MapFile.h parses the game .dat with almost no bounds checking — struct-at-offset memcpys with file-controlled sizes, unchecked uint32×uint32 multiplies, signed chunk-offset arithmetic that can overflow. A truncated/modded DAT (or wrong file from the setup wizard) → memory corruption instead of a load error. FFNA_ModelFile already demonstrates the fix pattern.
  • ATEX decoder: a confirmed && vs & bug (AtexDecompress.cpp:21 — AlphaDataSize2 is always 0, corrupting alpha-format block size), plus exit(0) on malformed texture data (one bad asset kills the app) and a type-punned delete[].
  • Unguarded exceptions on background threads: MatchIndex::ParseJson's throwing .get<int>() accessors run on SyncEngine's thread with no try/catch → std::terminate on a malformed remote file. Same risk in UpdateChecker.

4 Resilience gaps 2 agents

  • Device-lost is effectively unimplemented — ReplayWindow::OnDeviceLost/Restored are empty, MapBrowser's are TODO stubs; nothing recreates renderer resources / textures / meshes or re-inits the ImGui backend. A driver update leaves every open window on dangling COM pointers.
  • Self-update trusts transport only — downloads and installs an exe/zip with no signature/hash check (HTTPS + GitHub account control is the entire trust boundary), even though index.json already carries a size_bytes that's never verified.

5 Credentials & config 2 agents

  • R2 read credentials compiled into the shipped exe (extractable via strings), and the working-tree vs private-repo build_config.local.h carry two different key IDs with no marker of which is live or whether the stale pair was revoked. Bucket-wide read scope matters if private prefixes (scrims) ever share the bucket.
  • Contributor key stored plaintext in gui_settings.ini and passed on the push_builds.py command line.
  • Config duplicated across SetupConfig (%APPDATA%) and GuiGlobalConstants (gui_settings.ini) — drift hazard.

6 Performance & memory rendering + data

Per-frame blocking picking readback (CPU/GPU stall, no latency ring); no frustum culling anywhere; ~1 GiB 16384² shadow map in release; water-reflection RTs recreated every frame with a pipeline Flush(); unbounded texture caches holding a redundant full RGBA CPU copy per texture; stale transparency sort (never re-sorts on camera move); N devices × serial vsync Present (FPS drops ~linearly per open window). On the data side, every AgentSnapshot/StoC event retains its full raw_line string, 2–3×-ing replay memory.

7 Coupling via global mutable state core + UI

Panel↔core communication runs through inline header globals (g_pendingReplay, g_refresh*, g_modelViewerState) and a 500-line all-public GuiGlobalConstants static blob; pervasive function-local static state makes UI single-instance and untestable. ReplayMapData.h is a ~1.2K-line god-header dragging the render data model into the parse layer.

8 Documentation drift all 4 agents

CLAUDE.md misattributes spatial audio to BASS (it's XAudio2), understates ReplayWindow size by 70%, points at a solution path that doesn't exist, and names an animation file that isn't there; OVERLAY_DESIGN.md predates the instanced overlay.

Consolidated priorities

#ActionEffortWhy
1 Delete/gate the debug-dddcee.log blocks; fix the g_map_browser pre-construction call Trivial Real defects in the hottest, most-traveled paths, on every user's machine
2 Fix the ATEX bugs (&&→&, remove exit(0), harden size checks); verify RGBA/BGRA order Low Load-bearing RE path; a bad texture currently crashes the app
3 Harden FFNA_MapFile.h to the FFNA_ModelFile standard; wrap sync/update threads in try/catch Med Turns memory corruption / std::terminate into graceful load errors
4 Reconcile & rotate the two R2 key pairs; document the authoritative source; move toward presigned URLs Low–Med Live security / rotation ambiguity
5 Implement real device-lost recovery (or graceful teardown with a user message) Med Currently silent corruption on any GPU reset
6 Stop recreating shadow/reflection RTs per frame; make picking non-blocking; add frustum culling; drop shadow map to 4–8K Med Biggest frame-time wins, especially with multiple windows
7 Extract 6–8 feature clusters out of ReplayWindow.cpp (follow the draw_*.cpp pattern); replace the boolean-flag chain with a declarative build pipeline High The structural root cause behind most maintainability pain
8 Move builds.json fetch off the UI thread; debounce settings writes; unify path config; update the docs Low Removes first-paint hitches and per-frame file writes

Overall verdict

A capable, pragmatically-engineered tool with real strengths — phased loading, async discipline, secret layering, rigorous reverse-engineering — whose main liabilities are concentrated and addressable: a monolithic god object, a few leftover-debug / parsing-safety defects, absent device-lost handling, and credential-rotation hygiene. None of the top risks require architectural upheaval; priorities #1–#5 are largely bounded fixes.

▸ 1 Application core, control flow & build structure

Purpose & role

The skeleton of GW Observer: the process entry point and Win32 message pump (SourceFiles\Main.cpp), the main-application singleton MapBrowser (browser UI, DAT management, cloud sync, update checking, lifecycle owner of replay windows), and ReplayWindow — a per-match top-level window that owns its own D3D11 device, ImGui context, renderer, replay data pipeline, and every analytical feature. Build structure is a single VS2022 project with all third-party code vendored in-tree and feature/credential configuration injected at compile time via build_config.h.

Structure

  • Main.cpp (688 lines) — wWinMain, crash-dump handler with symbolized stack walk (15–104), window class + creation, BASS/BASS_FX runtime loading via GetProcAddress (249–304), main PeekMessage loop (309–322), WndProc (356–685) which also embeds model-viewer mouse handling.
  • MapBrowser.h/.cpp (2,215 lines) — main app object (DX::IDeviceNotify). Owns DeviceResources, MapRenderer, AgentOverlay, DATManager map, ReplayLibrary, FolderWatcher, the cloud stack, UpdateChecker, and std::vector<std::unique_ptr<ReplayWindow>> (MapBrowser.h:96–160).
  • ReplayWindow.h/.cpp — 1,133-line header; 29,161-line / 1.24 MB implementation — the per-match god object. (CLAUDE.md:56 says "~17K lines" — stale by ~70%.)
  • pch.h — precompiled header; also a grab-bag of app-wide helpers (DX::ThrowIfFailed, BASS typedefs at 85–103, file dialogs, LODQuality).
  • GuiGlobalConstants.h/.cpp — settings "singleton" as inline static public fields (517-line header), persisted via LoadSettings()/SaveSettings(), seeded from build_config.h.
  • build_config.h + build_config.local.h(.example) — version, cloud enable/host, developer mode, R2 credentials as preprocessor defines; local override discovered via __has_include or the adjacent private repo ($(ProjectDir)\..\gwobserver-private on the include path, vcxproj:95).
  • draw_*.cpp/h (30 files) — modular ImGui panels for the main window, driven from draw_ui() inside MapBrowser::Render() (MapBrowser.cpp:985).
  • Build: single project, Debug/Release × Win32/x64; 145 ClCompile entries; ImGui/DirectXTex compiled directly into the exe with PCH disabled per-file (vcxproj:377–380). Vendored: DearImGui 1.90.1-WIP, DirectXTex, ImGuiFileDialog, peglib, tinytiff (prebuilt libs), miniz, nanosvg; BASS DLLs extracted from exe resources at runtime. No package manager, no submodules.

Control flow

Startup (Main.cpp:163–307): SetUnhandledExceptionFilter → XMVerifyCPUSupport → CoInitializeEx(MULTITHREADED) → self-updater cleanup → register class → LoadSettings() → create window → InputManager + MapBrowser → BASS bind → MapBrowser::Initialize().

Main loop (Main.cpp:311–322): PeekMessage/Tick. MapBrowser::Tick() services replay-window plumbing first, then sync/update flags, then gates rendering (skip when minimized/unfocused) with a soft 60 FPS limiter (MapBrowser.cpp:492–522).

Replay windows: opening a match is requested via inline global g_pendingReplay, consumed in ProcessPendingReplayRequest(); cloud matches spawn a download thread polled in ProcessCloudDownloadResult(). Each ReplayWindow::Create builds its own HWND, its own D3D11 device, InputManager, MapRenderer, and ImGui context, sharing only the DATManager* and parent hash index by pointer.

Per-window tick (ReplayWindow.cpp:4204–5280): polls async parse completion, runs a chain of one-shot derivations guarded by ~21 boolean *Built/*Loaded/*Initialized flags, advances the clock, then dispatches the loading state machine Validate → Init → PropModels → PlaceProps → FadingOut → Ready/Error with time-budgeted batching (kLoadFrameBudgetMs = 30).

Threading: single UI/render thread; background workers communicate almost exclusively by std::atomic flags polled each frame (SyncEngine, cloud download, FolderWatcher, DATManager scan pool, per-window agent-model IO). Notably no std::mutex anywhere in ReplayWindow.cpp — correctness rests on polling flags and phase ordering.

Concerns / risks

  • ReplayWindow monolith — 29,161 lines in one TU; every feature a private member; any touch recompiles the world.
  • Implicit flag-driven state machine — ordering constraints encoded in comment prose ("before BuildTimelineData so…", :5176); a missed flag means silent recomputation or a stage that never runs.
  • Null-deref UB at first launch — Main.cpp:216 calls g_map_browser->GetDefaultSize(); object constructed at :231. UB on the exact path every fresh install takes.
  • Leftover debug instrumentation — #region agent log blocks synchronously append JSON to hardcoded D:\Guild Wars OBS\...\debug-dddcee.log in the frame loop (MapBrowser.cpp:541, 669, 911, 1053).
  • Dangling shared index hazard — replay windows hold a raw pointer to MapBrowser::m_hash_index, which Update clears/rebuilds on DAT switch (:567) while background threads may still read it.
  • Device-lost is a stub in replay windows — OnDeviceLost/Restored empty (:22308–22309) despite registering for notifications.
  • Global-flag message bus + input handling split three ways (WndProc model-viewer logic, InputManager, GetAsyncKeyState hotkeys).
  • Secrets baked into the binary; stale docs (solution path, line counts).

Recommendations (prioritized)

  1. Delete the debug logging blocks and fix the pre-construction call (make GetDefaultSize static or hoist construction).
  2. Extract per-feature classes from ReplayWindow following the draw_*.cpp pattern (CombatLog, EventTimeline, LordDamage, PianoRoll, SkillAnalytics, PlayerInfo, AutoCamera, FogOfWar, PiP).
  3. Replace the boolean-flag derivation chain with an explicit {name, deps, built, buildFn} build pipeline.
  4. Implement device-lost recovery (or graceful teardown) in ReplayWindow.
  5. Formalize shared-state ownership: shared_ptr<const HashIndex>, replace inline-global request flags with an event/request queue.
▸ 2 Rendering & graphics

Purpose & role

Turns recorded matches into an interactive 3D replay: loads local GW .dat assets, decodes ATEX/FFNA into GPU resources, renders a full scene (sky, clouds, terrain with splatting/shadows, static and skinned props, water with planar reflection, shore waves) via DX11 with a reverse-Z camera reconstructed from the retail client, then composites tactical overlays and a full ImGui UI. Not a standalone module — nearly all orchestration lives inside ReplayWindow and MapBrowser, with MapRenderer (a 1,741-line header-only class) as the scene renderer.

Rendering pipeline

Device/context (DeviceResources.cpp): each surface owns a full device + swapchain. Feature levels 11_1→9_1 (min 10_0), backbuffer R8G8B8A8_UNORM, depth D32_FLOAT, BufferCount=2, SWAP_EFFECT_DISCARD. MSAA applied directly on the swapchain backbuffer (so the flip/tearing plumbing at :603–617 is effectively dead). Present(1,0) blocks on vsync. Discrete-GPU selection via HIGH_PERFORMANCE + Nvidia/AMD export symbols.

Passes — (1) Shadow map, depth-only ortho, dirty-flag cached, RT 16384×16384 R32 in release (MapBrowser.cpp:1510–1516); (2) Water reflection, mirrored camera, re-rendered every frame, no dirty flag; (3) Clear depth to 0.0f for reverse-Z; (4) Scene: sky → clouds → terrain → opaque props → skinned props → water → shore → pathfinding → transparent props, with object-id picking written as MRT slot 1; (5) Overlays (heatmap, fog, agent models, cylinders), each wrapping ~14 pipeline-state items in manual save/restore; (6) Picking readback → ImGui → Present.

Camera (Camera.h/.cpp): left-handed look-to, reverse-Z (swap near/far, GREATER_EQUAL depth, clear to 0). Defaults fov 50°, near 10, far 200000. Reconstructed from the retail client.

Asset & texture pipeline

ATEX decode is four CPU stages then GPU upload: (A) DAT read + LZ decompress; (B) ATEX bitstream → BCn via AtexDecompress (reverse-engineered Huffman-like); (C) software BCn → RGBA on the CPU (GW textures are never uploaded as BCn); (D) upload as B8G8R8A8_UNORM with GPU GenerateMips. AtexAsm.cpp contains no inline asm — a hand-ported 64-bit-safe C++ decoder. Materials (AMAT) inform texture ordering + a blend hint only; the app uses its own HLSL shader set. Meshes: FFNA geometry → 3 LOD index buffers as IMMUTABLE.

Concerns / risks

  • Logical-vs-bitwise AND bug (confirmed): ((ImageFormat && 21) - 1) & 2 at AtexDecompress.cpp:21 — always 0, corrupting BlockSize for alpha formats. Almost certainly meant & 21.
  • exit(0) on malformed texture data (:9–11) kills the app; size checks only printf and continue. Type-punned delete[] (:48,162). Possible R/B channel-swap worth verifying.
  • ~1 GiB shadow map; reflection RTs recreated every frame with a full Flush(); unbounded texture caches with a redundant full RGBA CPU copy per texture built one push_back at a time.
  • Per-frame blocking picking readback (CopyResource + Map(READ), no latency ring); no frustum culling; per-draw CB Map/Unmap; command list copied by value; stale transparency sort (camera move never sets m_needsSorting); 4× sampler binds + forced AlphaBlend on every draw; frame-rate-dependent camera Walk/Strafe (ignores dt).
  • 4 of 6 blend modes are dead code; shader CB layout drift across sky/clouds/vertex shaders; static locals in MeshManager::Render shared across windows.
  • N devices, N serial vsync Presents — FPS drops ~linearly per open window, VRAM/driver overhead multiplies.
  • Device-lost recovery absent; hardcoded dev-path debug logging in the frame loop; sRGB inconsistency (everything _UNORM).

Recommendations (prioritized)

  1. Fix the ATEX correctness bugs (&&→&, drop exit(0), harden size checks, fix delete[], verify RGBA/BGRA).
  2. Stop recreating shadow/reflection RTs; remove per-frame Flush(); consider 4–8K shadow map; add reflection dirty flag.
  3. Make picking non-blocking (double/triple-buffer or click-only) and add AABB-vs-frustum culling.
  4. Fix draw-submission overhead + stale transparency sort; opaque geometry should use Opaque blend; multiply camera movement by dt.
  5. Implement real device-lost recovery; remove dev-only instrumentation; cap/evict texture caches and drop the redundant CPU RGBA copy.
▸ 3 Data, file formats & networking / replay stream

Purpose & role

Everything between bytes-on-disk/on-wire and the structures the renderer consumes. Three independent pillars: (a) cloud match distribution — Net\ fetches index.json + per-match .tar.gz from an R2/S3 bucket over WinHTTP (optional SigV4), extracts into a cache with LRU/time eviction, and self-updates via GitHub Releases; (b) replay ingestion — AgentSnapshotParser and StoCParser parse the recorder's gzipped, [MM:SS.ms]-stamped, semicolon-delimited text event logs into ReplayContext; (c) GW asset decoding — GWUnpacker/DATManager read Gw.dat, and the FFNA/BB8/BB9/FA0/FA1/ATEX parsers produce terrain, meshes, skeletal animation, and textures, fronted by the Cache\ layer.

Note: the "StoC protocol" is already decoded to text by the recorder, not raw binary packets. Python csv_to_header.py converts data.csv (735 map rows) into header_file.h — a manual offline codegen step.

File formats & parsers — validation quality

  • index.json / infos.json — good (non-throwing parse, .value() defaults) but v.get<int>() at MatchIndex.cpp:213,218,243 can throw with no try/catch on the sync thread.
  • Agent snapshots (46 positional ; fields) — good tokenizer, but schema is purely positional, no version/header.
  • StoC event logs (12 named files) — good per-type guards; field order differs per event type, documented only in comments.
  • tar.gz — decent: gzip walk, 512 MB decompress cap, zip-slip guard via weakly_canonical; whole archive held in RAM twice.
  • FFNA type 3 (maps) — weak: struct-at-offset memcpy with essentially no bounds checks (see risks).
  • FFNA type 2 (models) — mixed-to-good: data_size_bytes + parsed_correctly threaded through, sanity caps.
  • BB9/FA1 animation, BB8/FA0 geometry, file references, sound bytecode — the newer, well-guarded parser generation (offsets checked vs dataSize, optional returns, throws caught).

Caching

  • FileCache — thread-safe 512 MB LRU keyed by MFT index. Bug: hit/miss counters declared and reported but never incremented.
  • AnimationClipCache — binary sidecar keyed {mftIndex, fileHash}, invalidated by stored DAT size (size-only → a same-size swap serves stale clips).
  • CloudReplayProvider — 2 GB LRU (recomputes whole tree size per download) + 30-day retention via .last_played. LRU access times are in-memory only, so eviction order among untouched folders is effectively map-iteration order after restart.
  • Dead code: ModelCache.h's CacheManager::Initialize copies a mutex-owning class — couldn't compile if included; confirms it's unreferenced.
  • Memory: every AgentSnapshot retains its full raw_line; roughly 2–3×'s replay footprint and fragments the heap.

Concerns / risks

  • P1 — FFNA_MapFile.h parses with almost no bounds checking. Unvalidated terrain_x*terrain_y multiply (:630–632), signed chunk_data_size that can go negative then resize() huge (:699), chunk-scan adds 8+chunk_size to a signed int with no validation (:1865–1875) — corruption on a truncated/modded DAT rather than a load error.
  • P2 — Unhandled exceptions on background threads. MatchIndex::ParseJson throwing accessors + no try/catch in SyncEngine::SyncThread → std::terminate on a malformed remote file. Same risk in UpdateChecker.
  • P3 — Format versioning implicit everywhere. No recorder-version stamp; schema drift silently degrades. Archives carry no integrity check — size_bytes exists but is never compared, no hash.
  • P4 — Memory footprint: raw_line retention, per-download full-tree re-walk, double-buffered archives.
  • P5 — Self-update trusts transport only; installs via a batch script with no signature/hash validation.
  • P6/P7 — Nits & coupling: dead CacheManager, uncounted cache stats, ReplayMapData.h ~1.2K-line god-header dragging the render model into the parse layer.

Recommendations (prioritized)

  1. Harden FFNA_MapFile.h to the FFNA_ModelFile standard (bounded reader, checked arithmetic).
  2. Add try/catch (or non-throwing JSON access) around the sync and update threads.
  3. Version and verify the pipeline: stamp format_version in infos.json; compare downloaded size vs index; add per-match SHA-256 (also gives the updater a hash-verify template).
  4. Drop or gate raw_line retention; persist cloud LRU access times so eviction survives restarts.
  5. Delete dead cache code; wire up or remove FileCache stats; #pragma pack the structs whose sizeof participates in offset math.
▸ 4 UI, animation/audio, overlay/annotations, tooling, config & secrets

UI architecture

draw_ui.cpp:716–930 is the per-frame entry point, gating everything behind the first-launch wizard and loading screen, then menu bar (Debug menu compile-time gated by IsDeveloperMode()), DAT warnings, the always-visible replay browser, Settings, and modals. It takes ~14 reference parameters — wide, tightly coupled. Each panel is a free function in its own draw_*.cpp; visibility is a static bool on GuiGlobalConstants, persisted to gui_settings.ini — but save/restore/hide-all/reset are four parallel lists that must be kept in sync by hand.

Replay browser (draw_replay_browser.cpp, 3,788 lines) is the flagship: responsive layout, "glass" theme, fuzzy search, calendar picker, team-composition rendering — but also substantial non-UI logic: build detection, skill-template base-64 encoding, synchronous cloud fetch of builds.json, and a contributor push that shells out to python push_builds.py via std::system. DAT browser (3,718 lines) similarly mixes UI with DDS export and mesh generation. Two coexisting file-dialog systems: the vendored ImGuiFileDialog survives for only two legacy call sites alongside the hand-rolled CustomFileBrowser.

Animation & audio

Header-only animation stack: AnimationClip (parsed BB9 data), AnimationController (per-instance playback state machine, Update(dt)), AnimationEvaluator (samples to per-bone SRT, produces GPU skinning palette via Skeleton inverse-bind matrices, with several fallback strategies from incremental RE). Two audio engines: BASS (runtime-loaded, non-spatial DAT playback + animation sound events) and XAudio2/X3DAudio (SpatialAudioEngine) — the actual spatial engine used during replay: 32-voice pool, per-frame listener from camera, skill→sound map from settings/skill_sounds.json, robust scrub/seek cursor reset. Doc drift: CLAUDE.md:61 calls audio "BASS-based spatial" — spatialization is XAudio2.

Overlay & annotations

AgentOverlay — clean post-scene DX11 pass, instanced unit sphere, CB at slot b4, explicit state-restoration contract; dual-mode input (hot-reloaded agents.json polled every 150 ms, or programmatic SetMarkers()). AnnotationManager (1,635 lines) — arrow/circle/freehand/eraser tools anchored in world space (mouse ray × terrain) then projected to ImGui draw lists each frame, undo stack (50), distance fade, bookmarks. Persistence is asymmetric: bookmarks persist per match (bookmarks.json); drawings are session-only and lost on window close.

Configuration & secrets

Three stores: gui_settings.ini (hand-rolled INI; panel visibility, geometry, camera, and the contributor key in plaintext); %APPDATA%\GWObserver\config.ini (first-launch, EULA, paths, storage mode); settings/ (builds, skill_sounds, bookmarks, hotkeys, notes, ratings). DAT/match paths are duplicated across the first two.

Private-repo integration (clean design): build_config.h defines safe public defaults and pulls overrides via #if __has_include("build_config.local.h"); contributor keys via conditional include of contributor_key_hashes.h (GWO_VALID_KEY_HASHES), validated with BCrypt SHA-256. Hygiene verified: git ls-files shows only .example variants tracked; .gitignore covers all secret files; packaged gui_settings.ini has no key.

Secret-handling assessment (no values):

  • Read credentials are compiled into the shipped exe — extractable with strings; bucket-wide read scope matters if private prefixes ever share the bucket.
  • Two divergent credential copies (working-tree vs private-repo build_config.local.h) with different access-key IDs — rotation-discipline gap.
  • Contributor key exposed plaintext in gui_settings.ini and on the push_builds.py command line (charset-sanitized, but std::system + concat is fragile).
  • Validation is advisory — the real boundary is possession of the R2 write credentials in r2_config.env, which never ship. That's the right place for it.
  • Private repo history includes credential-file uploads; if its visibility ever changes, rotation is mandatory.

Auxiliary tooling

scripts/ — the R2 distribution pipeline (upload_to_r2.py with dry-run/validation, Upload-Manager.ps1 with scheduled task + webhook, push_builds.py), plus dated one-off maintenance scripts and ~17 FFNA RE analyzers. python_scripts/ — CSV→header codegen. blender_addons/ — import add-ons for inspecting FFNA assets. dist/ — unpacked release image + zip (gitignored).

Concerns / risks

  • Leftover #region agent log blocks ship in production — hardcoded D:\Guild Wars OBS\...\debug-dddcee.log written every 60 frames / every 150 ms overlay reload (AgentOverlay.cpp:305–316, ~5 blocks in MapBrowser.cpp).
  • Compiled-in cloud read credentials + rotation ambiguity.
  • Contributor key handled as plaintext (masked in the UI, not in storage).
  • UI-thread blocking network I/O — LoadBuildDefs does a synchronous HttpClient::Get inside the draw path; a slow host freezes first paint.
  • Monolithic panels with embedded domain logic; pervasive static state → single-instance, untestable.
  • Settings write amplification — full INI rewrite inside slider if(changed) handlers (a write per frame while dragging).
  • Duplicate config + duplicate file-dialog stacks; documentation drift; PushBuildsToCloud environment fragility (python on PATH, fire-and-forget std::system); annotation drawings not persisted while bookmarks are.

Recommendations (prioritized)

  1. Strip (or dev-gate) the #region agent log blocks.
  2. Reconcile and rotate the R2 read credentials; document the single source of truth; prefer presigned URLs / a public read domain over compiled-in keys.
  3. Move builds.json fetch off the UI thread (reuse the SyncEngine pattern).
  4. Extract domain logic out of draw_replay_browser.cpp (BuildDefs module, cloud push into Net/ with an authenticated PUT instead of std::system — also fixes command-line key exposure).
  5. Debounce settings persistence (save on release/close); unify path config under SetupConfig; update docs; persist annotation drawings.
